# 为 StarBench 写 Skill

Skill 是一个文件夹，里面有一份 `SKILL.md`：开头的元信息写名字和说明，后面的正文是给模型看的做事说明。StarBench 每次请求都把所有 Skill 的名字和说明发给模型，模型觉得用得上时调用 `load_skill` 读正文；用户也可以在输入框里输入 `/` 直接选一个，这时正文随消息一起发出。所以说明决定 Skill 会不会被用上，正文决定用得好不好。

## 步骤

1. **问清楚要教什么**：让模型做什么事；用户平时会怎么开口要它做；先后有哪些步骤；有没有固定的格式、规矩或者不许做的事；好的结果是什么样子。用户已经说了的不要再问，缺的一次问完。
2. **起名字**：只用英文字母、数字、`-` 和 `_`，以字母或数字开头，最长 64 个字符，例如 `weekly-report`。文件夹用同一个名字。名字不合规时 StarBench 改用文件夹名；文件夹名也不合规（比如用了中文），这个 Skill 就不会出现，也没有任何提示。Skills 清单里已经有同名的，换一个名字，或者先问用户是不是要替换它。
3. **写说明**：一两句话，先说做什么，再说什么时候用，带上用户会说的话。说明每次请求都要发送，尽量控制在 100 个字以内；超过 600 个字符的部分会被截掉。
4. **写正文**：照下面的"正文怎么写"。
5. **写进文件**：见"写在哪里"。
6. **告诉用户怎么装、怎么试**：设置 → Skills → 打开 Skills 文件夹，把这个文件夹放进去，不用重启就生效。先在输入框里输入 `/` 选它，用一个真实的请求试一次；再不用 `/`，提一个该用它的请求，看模型会不会自己去读。不会的话，改说明。

## 正文怎么写

- 写给模型看，用祈使句：先做什么，再做什么，做完怎么检查。
- 只写模型自己不知道的：这个人或团队的做法、固定的格式、容易出错的地方。"代码要清晰"这类常识不用写。
- 要执行的命令写具体。StarBench 在 Windows 上用 PowerShell 5.1 执行命令（不支持 `&&`，用 `;` 或者分成几条），在 macOS 和 Linux 上用 `/bin/sh`。只适用于一种系统的，在正文里写明。
- 有固定格式的结果，给一个完整的样例。
- 写明哪些事要先问过用户，比如提交、删除、把东西发出去。Skill 改不了 StarBench 的确认规则：写文件和执行命令问不问用户，由应用和用户自己的选择决定。不要写"直接执行，不用问"这类话。
- 篇幅控制在一两屏。模型读取时正文整段进入上下文，太长会挤掉对话，小模型更吃力。较长的资料放进附带文件。
- 正文用用户的语言写。

## 附带文件

- 模型读取正文时，会拿到 Skill 文件夹的路径和里面的文件清单（最多列 50 个）。要用某个文件时，用 `load_skill` 的 `file` 参数读（只能读文本，不超过 1 MB）；脚本用执行命令按绝对路径运行。
- 在正文里写明每个附带文件是什么、什么时候读或运行，否则模型不会去碰它。
- 不要放密钥、密码和个人信息。

## 格式

元信息只读 `name` 和 `description`，其他字段会被忽略。值里有冒号没关系；说明太长时可以写成 `description: >`，下一行起缩进续写。

```markdown
---
name: weekly-report
description: 按团队的格式写周报。用户要写周报、整理这周做了什么时使用。
---

# 写周报

## 步骤

1. ……
2. ……

## 格式

……
```

一个完整的例子见附带文件 `example.md`（教模型写提交信息的 Skill）。

## 写在哪里

- 模型的文件工具只能写工作文件夹里的文件，所以在工作文件夹里新建 `<名字>/SKILL.md`。同名文件夹已经存在时，先问用户。
- 工作文件夹是一个项目时，告诉用户装好之后把这个文件夹从项目里删掉。
- 工作文件夹就是 Skills 文件夹本身时（用户这样说，或者路径以 `StarBench\skills`、`StarBench/skills` 结尾），直接写在里面，写完就生效。
- 修改已经装好的 Skill：Skills 文件夹在工作文件夹外面，读写不到。先用 `load_skill` 读出它现在的正文和附带文件，在工作文件夹里写出改好的整套，再请用户换掉原来的。插件带来的 Skill 不要去改插件的文件夹：在用户自己的 Skills 文件夹里放一个同名的，StarBench 就用它代替插件的那个。

## 写完检查

- 文件夹名和 `name` 一样，只用英文字母、数字、`-`、`_`
- 说明写了做什么、什么时候用，在 100 个字左右以内
- 正文是步骤和规矩，不是介绍
- 命令在 PowerShell 和 `/bin/sh` 下都能执行，或者写明了只用于哪个系统
- 正文提到的附带文件都在，文件夹里的每个附带文件正文都提到了
- 没有密钥、密码和个人信息
