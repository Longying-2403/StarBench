# 撰写提交信息

## 步骤

1. 运行 `git status --short` 和 `git diff --staged`，确认这次要提交的内容。暂存区为空时改看 `git diff`，并告诉用户还没有暂存任何文件。
2. 判断这些改动是不是同一件事。如果混着互不相关的改动，建议拆成几次提交，不要硬写成一条。
3. 按下面的格式写出提交信息，先给用户看，得到同意后再执行 `git commit`。

## 格式

- 第一行是摘要：用祈使语气说明这次提交做了什么，不超过 50 个字符，结尾不加句号。
- 第二行留空。
- 正文说明为什么要改，以及读代码看不出来的背景。改了什么由 diff 说明，不必复述。
- 正文每行不超过 72 个字符。

## 注意

- 不要写"修复 bug""更新代码"这类看不出内容的摘要。
- 提交信息的语言和仓库里已有的提交保持一致，可以先用 `git log --oneline -5` 看一眼。
