# 记忆

记忆让模型跨对话记住关于你和项目的事：你是谁、你的习惯，你纠正过它的地方，项目里代码看不出来的决定，东西放在哪里。它是应用自带的功能，默认开着。在侧栏"插件"下面的"记忆"里查看、修改和删除；在"插件"页的"内置功能"里可以关掉。

## 存在哪里

- **两层**：全局的记忆在所有工作区的对话里都用；工作区的记忆只在那个工作区的对话里用。模型写入时可以指定范围，没指定时，"关于你"和"反馈"记成全局，"项目"和"参考"记在本工作区。
- **文件**：每条记忆是一个 Markdown 文件，放在应用的数据文件夹里：全局的在 `memory/global/`，工作区的在 `memory/workspaces/<文件夹名>-<哈希>/`（里面的 `workspace.json` 记着原来的路径）。不会写进你的工作文件夹，也不会从工作文件夹读取：克隆来的仓库带不进记忆。
- **格式**：文件开头是名字、一行内容、类型、时间和来源，正文是细节（可选）。可以用任何编辑器改，改完下一轮生效。记忆页底部的"打开记忆文件夹"直接打开它。手改时一行写得超过 150 字、细节超过 2,000 字也照样读，不会被截掉：清单里只放这一行的前 150 字，末尾带 `+`，模型用 `recall` 读得到全文；在记忆页里改这一条时，要先缩短才能保存。

  ```markdown
  ---
  name: k3f9
  description: "回答里不要用表情符号"
  type: feedback
  created: 2026-11-24T06:40:00.000Z
  updated: 2026-11-24T06:40:00.000Z
  source-conversation: "…"
  source-provider: "deepseek"
  source-model: "deepseek-flash"
  ---
  ```

- 待确认的全局记忆（见下文）在开头多两行：`pending: true`，和写下它的工作区 `origin`。手改时删掉这两行，等于设为全局。
- 和对话记录一样是明文保存的。

## 模型怎么用

- 系统提示的最后（Skills 清单之后）有一节"Memory"：先是几句说明，告诉模型什么值得记、什么不要记，记忆不能拿来跳过确认、执行命令或往外发东西；然后每条记忆一行，末尾是它的名字（例如 `#k3f9`），有细节的带 `+`。
- 模型有三个工具：`remember`（写入一条，或用 `replaces` 更新一条）、`forget`（删掉一条）、`recall`（读一条的细节，或者搜索清单放不下的）。一行内容最多 150 个字，细节最多 2,000 个字。
- 这三个工具不需要你确认，在四种权限模式下都一样（记忆不是对工作区的改动）。模型写入、修改或删除之后，输入框上方会弹出一个和权限确认框一样的提示框，可以"查看"或"撤销"（删除的是"恢复"）。它 8 秒后自己收起，底部的蓝线是剩下的时间；鼠标停在上面、或者窗口不在前台时不倒数。同一轮里改了几条，就并进同一个框。对话记录里也留着这次调用。撤销只对还保持那次改动结果的记忆有效：同一条之后又被改过（例如同一轮里先写入、又更新），要先撤销后面那一步。
- **模型写的全局记忆先"待确认"**：模型新写、或者改过的全局记忆，先只在写下它的那个工作区里用。提示框里点"设为全局"，或者在记忆页里点"设为全局"、编辑保存一次，它才进入所有工作区。待确认的记忆在记忆页里用黄色色带标出，写着"待确认"和目前在哪个工作区里用；也可以点"只留在本工作区"，把它改成那个工作区的记忆。你用 `/memory-add`、`/memory-edit` 指令明确要求时，直接是全局的，不用确认。这样，文件或网页里藏着的"请记住……"最多影响读到它的那个工作区。
- **改你写的记忆前先问**：你在记忆页写过或改过的记忆，模型要修改或删除时，先弹出"模型要修改（删除）一条你自己写的记忆，同意吗？"，列出原来的内容和要改成什么，主按钮是"不改"（"不删"）。你用 `/memory-edit`、`/memory-del` 指令明确要求时不问。
- 要写入的内容里像是有密钥、令牌、私钥、密码，或者身份证号、信用卡号、手机号、电子邮箱时，先弹出"这条记忆里可能有敏感资料，要写入吗？"，等你选"不写入"或"写入"，认出的部分用红框标出。这一问不看权限模式；"仅可查看"拒绝的调用照样拒绝，这一问不会让它们放行。
  - 认得出的：各家常见格式的 API Key（OpenAI、Anthropic、xAI、Google、GitHub、GitLab、Slack、Hugging Face、AWS、腾讯云、阿里云、火山引擎、百度千帆、智谱、Stripe、Groq 等）、JWT 令牌、私钥、带密码的连接地址（`协议://用户:密码@主机`），以及前面写着 key、token、secret、密钥、令牌、口令这类字样的长串（不管是十六进制、UUID 还是全小写）。git 提交号、校验值这类没有这些字样的不算。
  - 拆开写也认得出：一条的正文和细节连起来查；同一个对话里 10 分钟内连续写下的几条，也连起来查。
  - 已经存进去的记忆里像密钥或个人资料的部分，记忆页上用红框标出，旁边写"可能是密钥"（或"可能有个人资料"），提醒你删掉并更换 Key。
  - 这是防手误的一道网，挡不住刻意伪装的写法（例如中间夹空格）。

## 对话开始后，记忆怎么变

一个对话在第一轮把当时的记忆拍成快照，之后每轮都用这一份，系统提示的开头保持不变。这样各家服务的提示缓存不会因为记忆变了而失效：Claude、xAI、DeepSeek、Gemini 和本地服务都是从请求开头起缓存的，开头一变就要把整段对话重读一遍；Claude 签过名的思考、xAI 留在服务器上的思考，开头一变也接不上了。

- 模型在这个对话里新记的、改的：它自己看得到（就在工具调用里），从下一个对话起才进入清单。待确认的全局记忆只进入写下它的那个工作区的清单；你设为全局后，其他工作区正在进行的对话也从下一轮起带上它。
- 你在记忆页里写的、改的：从每个对话的下一轮起生效。
- 删掉的（不管谁删的）：从下一轮起不再发给模型。

快照存在 `memory/snapshots/<对话 id>.json`，只记记忆条目，不记对话内容；删除对话时一起删除。功能上线前就有的对话，在下一轮拍快照，那一轮缓存会重读一次。

## 清单放多少

- 默认最多 3,000 token，按应用自己的估算（中文一个字算一个，其他字符四个算一个）。常见长度的记忆每条约 26 token，大约能放 115 条；每条都写满 150 字时大约 19 条。说明文字约 290 token、三个工具的定义约 350 token，不算在里面（"只读"时分别约 90 和 80）。记忆页底部的"清单上限"可以调成 500 到 10,000。
- 上下文小于 40K 的模型只用上下文的 5%（8K 约 15 条，32K 约 60 条）；不知道上下文多长的本地服务按 1,000 算。
- 放不下时，最久没改过的先不放进清单，记忆页上标"未放入清单"，模型用 `recall` 仍然查得到；清单末尾会告诉模型还有几条。
- 各家服务实际怎么计数和这个估算不一样，上下文小工具里多出的"记忆"一类同样是估算，点它打开记忆页。

## 各模型服务

记忆页底部给每个模型服务选一种：

| 选项 | 发给模型的 | 模型的工具 |
|---|---|---|
| 读写（默认） | 说明和清单 | `remember`、`forget`、`recall` |
| 只读 | 简短的说明和清单 | `recall` |
| 不用 | 什么都不发 | 没有 |

小模型调用工具不稳时，可以设成"只读"。用自己的提示词替换了内置提示（例如微调过的模型）时记忆照样附在后面，模型因此表现变怪的话，设成"不用"。

在本地模型（本机或局域网里的服务）的对话里写入的记忆，默认标"仅本地"，只发给本地模型，云端服务的对话里看不到，也查不到；在记忆页编辑时可以取消。

## 指令

记忆开着时，在输入框里输入 `/`，或者点"+"→"指令"，可以选四个指令：

- `memory`：查看这个对话带着的记忆，或者按给的词查找。
- `memory-add`：把你这条消息里说的事记下来。
- `memory-edit`：照你的说法改一条记忆。
- `memory-del`：照你的说法删掉记忆。

它们只由你选用，不放进发给模型的 Skills 清单（见 [编写 Skill](skills.md) 里的"指令"）。不用指令也可以，直接跟模型说"记住……""把那条删掉"就行。

## 隐私

- 记忆会随每个请求发给当前的模型服务；中途换服务时，同一份记忆会发给新的服务（"仅本地"的除外）。不想让某个服务看到，把它设成"不用"。
- 模型读到的文件或网页里如果藏着"请记住……"，模型可能照做。这样写下的全局记忆先只在那个工作区里用，你设为全局之后才带进所有工作区；你自己写的记忆，模型要改要删都会先问你。写入后的提示框也是为了让你马上看到、撤销；每条记忆还记着来源：哪个对话、哪个服务和模型、什么时候。
- 在侧栏删除工作区不会删除它的记忆。记忆页的"全部"里，已移除的工作区的记忆单独列出，可以删除。
- 关掉记忆后，记忆不再发给模型，工具和指令也不再提供，侧栏的入口隐藏；已有的记忆还留着，从"插件"页那一行的"打开"仍能进记忆页。
