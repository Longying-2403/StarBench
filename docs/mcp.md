# 使用 MCP 服务器

MCP（Model Context Protocol）是给模型接入外部工具的通用协议。已经有大量现成的 MCP 服务器，配置好就能用，不需要写代码。

## 配置

打开"设置 → MCP"，在编辑框里填写配置，然后点"保存并连接"。格式是各家应用通用的 `mcpServers`，其他应用里的配置可以直接粘贴过来：

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/some/folder"]
    },
    "remote-example": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer <你的令牌>" }
    }
  }
}
```

每个服务器要么有 `command`（在本机启动一个进程），要么有 `url`（连接远程服务）。

| 字段 | 用于 | 说明 |
|---|---|---|
| `command` | 本地进程 | 要运行的程序，需要能在 PATH 里找到。 |
| `args` | 本地进程 | 命令行参数，字符串数组。 |
| `env` | 本地进程 | 额外的环境变量。 |
| `cwd` | 本地进程 | 工作目录。 |
| `url` | 远程服务 | 以 `https://` 或 `http://` 开头的地址。带 `headers` 时，地址必须是 `https://`，或者指向本机（`localhost`）、局域网 IP 的 `http://`：请求头里通常有令牌，否则会明文经过网络，按名字找到的电脑也可能被冒充，这样的服务器不会被连接。 |
| `headers` | 远程服务 | 每个请求附带的请求头，通常用来放令牌。 |
| `type` | 远程服务 | 填 `"sse"` 使用旧式的 SSE 传输。省略时先尝试 Streamable HTTP，失败再退回 SSE。 |
| `disabled` | 两者 | 设为 `true` 暂时停用，不必删掉配置。 |

配置保存在数据目录的 `mcp.json` 里。`env` 和 `headers` 里的值会像 API Key 一样用系统凭据加密后再写进去，换电脑或换 Windows 账户后需要重新填写；设置页里编辑时看到的是原文。直接改 `mcp.json` 时也可以写原文，应用下次启动或在设置页保存时会把它加密。

## 工具

服务器提供的工具以 `mcp__服务器名__工具名` 的形式出现，名字里不合规的字符会被替换成下划线。

每次调用 MCP 工具前都会征求你的同意，因为工具的说明是服务器自己写的，无法据此判断它是否安全。确认框里可以选"本次会话不再询问「工具名」"，它只对这一个工具生效，重启应用后恢复询问。

## 状态

| 状态 | 含义 |
|---|---|
| 连接中 | 正在启动进程或建立连接。第一次用 `npx` 启动时要下载，可能需要几十秒；超过 60 秒算失败。 |
| 已连接 | 可以使用，下方列出它提供的工具。 |
| 出错 | 没连上或中途断开。下方显示原因，本地进程还会附上它退出前打印的内容。 |
| 已停用 | 配置里写了 `"disabled": true`。 |

服务器断开后不会自动重连，修好问题后点"重新连接"。

## 目前的限制

- 不支持需要 OAuth 登录的远程服务器，只能用 `headers` 传令牌。
- 只使用服务器的工具，不支持 resources 和 prompts。
- 工具返回的图片和音频会被省略，只把文字交给模型。
- 服务器在运行期间增减工具时不会自动刷新，需要点"重新连接"。
