# 编写 Skill

Skill 用来教模型按某种流程或规范做事。它不是代码，而是一个文件夹加一份 `SKILL.md` 说明文档，格式与 Anthropic 的 Agent Skills 相同。

## 它是怎么起作用的

- 模型在每次对话里都能看到所有 Skill 的**名字和说明**。
- 当它判断某个请求用得上时，会调用 `load_skill` 读取**正文**，然后照着做。
- 你也可以手动指定：在输入框里输入 `/`，或点"Skills"按钮选择。这时正文会随消息一起发给模型，不依赖它自己判断。

所以说明决定 Skill 会不会被用到，正文决定用得好不好。

## 安装

1. 打开"设置 → Skills → 打开 Skills 文件夹"。
2. 把 Skill 文件夹放进去。

放进去就生效，不需要重启。仓库里的 [`examples/skills/commit-message`](../examples/skills/commit-message) 是一个示例。

## 格式

```
my-skill/
  SKILL.md
  checklist.md        可选：补充资料
  scripts/check.py    可选：脚本
```

`SKILL.md` 以一段元信息开头，后面是给模型看的正文：

```markdown
---
name: code-review
description: 审查代码改动。用户要求 review、检查 diff 或在提交前把关时使用。
---

# 代码审查

1. 先运行 `git diff` 看完整的改动……
```

| 字段 | 说明 |
|---|---|
| `name` | Skill 的名字。只能用字母、数字、`_` 和 `-`，最长 64 个字符。省略或不合规时用文件夹名。 |
| `description` | 这个 Skill 做什么、什么时候该用。模型只凭这段话决定是否读取正文，所以要写出触发的场景。过长的部分会被截断（上限 600 个字符）。 |

## 附带文件

Skill 文件夹里的其他文件不会自动发给模型。读取正文时，模型会得到这个文件夹的路径和文件列表，需要时再用 `load_skill` 的 `file` 参数读取某个文件，或者用"执行命令"工具按绝对路径运行脚本。

在正文里说明每个文件的用途，模型才知道什么时候去读它。

## 重名

同名的 Skill 只有一个生效：你自己的 Skills 文件夹优先，其次是插件带的，最后是应用自带的。

## 随插件分发

插件可以在自己的文件夹里放一个 `skills/` 目录，里面的每个子文件夹都是一个 Skill，插件启用时生效、停用时消失。只有 Skill 没有代码的插件也可以：这时不需要 `index.js`，只要 `package.json` 和 `skills/`。

## 随应用安装的 Skill

StarBench 自带两个 Skill（[`skills/`](../skills)），不用安装，一直可用，在"设置 → Skills"里带着"内置"标记：

- `create-skill`：帮你写 Skill。
- `create-plugin`：帮你写 StarBench 插件。

它们知道 StarBench 读取的格式，会把写好的文件夹放在工作文件夹里，再告诉你放进哪里。想换一种做法，就在你自己的 Skills 文件夹里放一个同名的 Skill，用的会是你那一份。应用自带的那份在安装目录的 `resources\skills` 里，可以复制出来改。

## 安全须知

Skill 的正文是给模型的指令。来源不明的 Skill 可能让模型去做你不希望它做的事，附带的脚本也只是普通的程序。安装前请读一遍。模型执行命令和修改文件前仍然会征求你的同意；如果在确认框里选了"本次会话不再询问"，这个对话里之后的同类操作就不再询问。
